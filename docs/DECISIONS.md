# Decisions

## 2026-10-18: Independent Cloudflare candidate with an isolated rebuildable cache

The existing Deno VPS service remains deployed and keeps its in-memory/file cache unchanged. The additional Worker runs the same portable health handlers, native fetch probes, discovery parser and dashboard assets independently; it never proxies the health API to the VPS. Bun provides a separate local listener and file cache.

The Worker stores externally submitted health observations in the isolated `uos-health-candidate` D1 database through `UOS_HEALTH_CACHE`. Existing cache values have no TTL, CAS, range queries or authoritative user state. Updates replace one app/plugin key and advance the global timestamp atomically; reads go to the D1 primary. We do not use eventually consistent Workers KV because immediate reads after POST are supported by the existing API and eventual stale-read tolerance has not been established. The legacy update response keeps `storage: "deno-kv"` for consumer compatibility; it does not describe the actual storage backend.

No existing cache data is copied, no store is shared with the VPS, and no hosted scheduler is added. Browsers retain their five-minute domain-check cadence. The dashboard does not submit `/health/update`; external clients alone repopulate `/health/cache` and `/json`. An initially empty candidate cache is expected and must not be presented as successful discovery.

The Worker has no canonical routes and no Cron Triggers. The only deployment target is the public `uos-health-candidate` workers.dev service. Production route ownership remains unchanged. The retained Deno deploy workflow is manual-only (`workflow_dispatch`) so task branches and ordinary pushes cannot accidentally redeploy the legacy hosted runtime; its recovery resource and deployment inputs are retained. This does not change the VPS service. Removing or changing the candidate cannot roll back or modify VPS data; D1 data is independent of Worker code rollback.

The existing discovery URLs `https://ubq.fi/sitemap.json` and `https://ubq.fi/plugin-map.json` return 404 as of 2026-10-18. Router catalog/discovery removal was deliberate in commit `912b59bd0132506a92b7858858c16edcbe23ba0c`. The user explicitly chose to restore the historical GitHub source: the public `ubiquity` and `ubiquity-os-marketplace` organization repository APIs, with no token or new secret. Apps include the apex repository and `.ubq.fi` suffixes; plugin domains preserve the historical `os-` prefix and `main`/`development` variants. Archived repositories remain included, while invalid DNS-derived metadata names cannot become probe targets. Catalog membership does not prove a deployed service and public GitHub APIs do not enumerate private services.

GitHub Link pagination is limited to the same organization API path and a shared 12-request budget. Catalogs are cached for five minutes, with the Worker's last-known-good catalog persisted separately in D1. Cold source failures return an error; refresh failures preserve valid observations and expose stale/error metadata to the dashboard. Native runtime fixtures prove behavior separately from live public GitHub acceptance. No router or apex deployment is changed.

Concurrent catalog misses use a D1 atomic owner/expiry lease across isolates, with a second cache read after admission to close the cache-read/claim race. A lease lasts 45 seconds, while refresh I/O has a 30-second overall deadline; only its unexpired owner may save a catalog, and release is owner-checked. Failed requests release their lease and abandoned leases expire. Local adapters use a boolean admission guard. Concurrent callers reuse last-known-good data, or receive HTTP 503 with `Retry-After: 1` when the cache is cold; no in-flight request I/O promise is shared. This resolves the substantiated P2 review finding, reproduced in actual workerd as eight overlapping organization crawls before correction.

Current official Workers Free limits are 10 ms CPU, 50 external subrequests per invocation and 100,000 daily account requests; D1 includes 5 million daily row reads and 100,000 row writes. Each health domain is checked in its own HTTP invocation, rather than combining all domains into one fanout. D1 updates use a transaction; table and primary-key index writes both count. These are shared account allowances and the public API retains its existing unauthenticated update authority; this change does not establish abuse resistance or unlimited capacity.

The reproducible toolchain is Bun 1.4.0, Wrangler 4.151.1, Miniflare 5.20261012.1-beta, TypeScript 5.9.3 and supported Node 24 for Cloudflare tooling only. Worker tests execute the production bundle in actual workerd with isolated upstream Workers and real local D1, separately from Bun listener and retained Deno regression checks.
